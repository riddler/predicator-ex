# Predicator-ex extension: /wurk:commit

ISA analysis, the corpus discipline, and this project's changelog and testing
conventions. Adds only - see `~/.claude/skills/wurk:commit/SKILL.md` for
everything this does not repeat.

## ISA-bump analysis

Before committing, ask whether the diff touches `lib/predicator/instructions.ex`,
`docs/isa.md`, or the corpus. If it moves the instruction set, the commit
message owes the version, the `docs/isa.md` entry, and a corpus explanation in
the body (ADR-0003).

## A corpus diff gets explained

`conformance/corpus/*.json` and `conformance/manifest.json` are generated by
`mix corpus.generate` and never hand-edited; the authored source is
`conformance/cases/*.json`. Name the cause of a corpus diff in the commit
message and the PR body.

## Changelog: fragments in `changelog.d/`

`changelog.mode` is `fragments` here. When the diff changes observable
behavior of `Predicator.evaluate/3` or the predicate language, write a
fragment named for the issue (`changelog.d/px-abc.md`) per
`changelog.d/README.md`. Never add entries to `CHANGELOG.md` directly -
fragments are assembled into it only at release, which is release work under
CLAUDE.md's authority table, not commit work.

## The binding-test sabotage note convention

The enumerated tests that bind an exported artifact to its source carry a
sabotage note - broken deliberately, confirmed red, then reverted and
confirmed green, per `docs/research/260808-px-9ab-sabotage-notes.md`.
Ordinary tests carry no note. This is a narrow, enumerated list, not a
blanket policy: do not import statifier's every-new-test sabotage protocol
here.

## Diff-classification vocabulary

Tokens, AST nodes, instructions/opcodes, visitors, corpus tiers.

## The stale-corpus recovery

When `corpus_freshness_test.exs` is red, the fix is always
`mix corpus.generate` plus reading the resulting diff - **never** an edit to a
file under `conformance/corpus/` or to `conformance/manifest.json` to force it
green. A surprising diff is itself a finding, not a nuisance to silence.

## User-facing, defined

Predicator is a published Hex package: a user is anyone calling
`Predicator.evaluate/3` or writing predicate source. A new operator,
function, or instruction qualifies as user-facing.

## No version-bump ritual on a feature branch

`@version` in `mix.exs` moves only for a named release, never as a side effect
of a commit.
