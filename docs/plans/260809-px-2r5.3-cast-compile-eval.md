# Cast Compilation and Evaluation Implementation Plan

## Overview

Take the `{:cast, expr, type_name, position}` AST node that `px-2r5.2` already
parses and carry it the rest of the way: emit a new `cast` opcode from the
compile path, implement the full conversion matrix in the evaluator, and land
the ISA v4 paperwork that minting an opcode owes (ADR-0003). Beads issue:
`px-2r5.3`, a child of the `px-2r5` epic, unblocked by `px-2r5.2` and governed
by [ADR-0011](../adr/0011-casts-are-an-opcode.md).

After this bead, `Predicator.evaluate(~s("42"::integer > 5))` runs end to end.

## Current State Analysis

**The AST node exists and nothing consumes it.** `px-2r5.2` landed the `::`
token, the postfix production, the seven-name vocabulary check, and the node
itself (`lib/predicator/parser.ex:111`, `:147`, `:168`, `:1032-1044`). A grep
for `:cast` across `lib/` finds hits only in the parser. Neither
`InstructionsVisitor` nor `StringVisitor` has a clause, and neither has a
catch-all, so a parsed cast reaching either raises `FunctionClauseError` today -
the interim gap `px-2r5.2`'s plan recorded and accepted. **This bead closes the
`InstructionsVisitor` half; the `StringVisitor` half stays open until
`px-2r5.4`.**

**The compile path is uniform and short.** `Predicator.Compiler` holds no
AST-walking logic; it delegates to `Visitor.accept/3` and to
`InstructionsVisitor.visit_with_positions/2` /
`visit_with_segment_positions/2` (`lib/predicator/compiler.ex:56-59`, `:88-92`,
`:113-118`). Every node's compile clause lives in the private
`visit_annotated/2` dispatch
(`lib/predicator/visitors/instructions_visitor.ex:170-347`) and returns
`{instruction, position}` pairs; the position side table is derived generically
from those pairs by `tables/1`
(`lib/predicator/visitors/instructions_visitor.ex:139-162`), so a new clause
"registers" its position simply by pairing its instruction with the node's own
position slot. `property_access`
(`instructions_visitor.ex:185-189`) is the exact model: visit the child, then
append one `{["access", property], position}` pair.

**The evaluator's opcode shape is equally uniform.** Each opcode is one
`execute_instruction/2` clause guarded on its operand shape
(`lib/predicator/evaluator.ex:446-603`), delegating to a private
`execute_<opcode>/N` helper that pattern-matches the stack for its depth check
and replaces the popped values in place. A malformed operand falls through to
the catch-all `unknown_instruction` clause (`evaluator.ex:601-603`) - which is
exactly the standing rule ADR-0011 relies on for a `cast` whose operand is not
one of the seven names. Insufficient operands is
`EvaluationError.insufficient_operands/3`
(`lib/predicator/errors/evaluation_error.ex:60-75`). `:undefined` is the literal
atom, `Predicator.Undefined.value/0`.

**Nothing in the tree converts values today**, which is the point of ADR-0011's
Context section. What exists and is reusable:

- `Predicator.Duration.to_string/1` (`lib/predicator/duration.ex:278-297`) -
  largest-unit-first, zero components omitted, `"0s"` when empty. This is
  already the format the research doc specifies for `duration::string`.
- `Predicator.Duration.new/1`, `from_units/1`, `add_unit/3`
  (`duration.ex:35-110`) - build a duration map. `add_unit/3` accepts exactly
  the eight short suffixes `y mo w d h m s ms`.
- Stdlib `Date.from_iso8601/1` and `DateTime.from_iso8601/1`, already used at
  `lib/predicator/lexer.ex:653-665` and
  `lib/predicator/conformance/values.ex:115-127`. `DateTime.from_iso8601/1`
  returns `{:error, :missing_offset}` for a naive string, which is precisely the
  research doc's `::datetime` rule with no extra code.
- **No duration string parser is reachable.** The duration-literal grammar lives
  in private lexer functions (`lexer.ex:670-750`); `extract_duration_unit/1`
  (`:712-739`) and `duration_unit?/1` (`:741-749`) show the accepted set is
  exactly `y mo w d h m s ms` - the same eight suffixes `Duration.to_string/1`
  emits, which is what makes `d::string::duration` round-trip.
- **No number-formatting or number-parsing helper exists.** `Float.to_string/1`
  is Elixir's shortest-round-trip printer and is the whole of what
  `float::string` needs.

**The ISA surfaces are bound to each other by tests, and they are strict.** Five
separate guards fire the moment `"cast"` enters `Predicator.Instructions`'s
`@opcodes` map:

1. `test/predicator/isa_sync_test.exs:30` - `@opcode_count 27` is asserted
   against the row count of `docs/isa.md` §4's table.
2. `isa_sync_test.exs:163-204` - every live opcode must have an
   `execute_instruction/2` clause head, and every clause head must be a known
   opcode. The two land together or the suite is red.
3. `isa_sync_test.exs:65-88` - `isa_version/0` must equal the maximum version in
   the table, and §1's `Current version: **ISA vN**.` line must agree.
4. `test/predicator/conformance/opcode_coverage_test.exs:34-47` - **every opcode
   in `opcode_set(isa_version())` must appear in at least one authored
   conformance case**, or be a documented exclusion in both that test and
   `conformance/README.md`. This is the constraint that pulls corpus work into
   this bead.
5. `test/predicator/conformance/corpus_freshness_test.exs:20-31` - the
   checked-in `conformance/corpus/tier-*.json` and `conformance/manifest.json`
   must be byte-identical to what `mix corpus.generate` would write. The
   manifest embeds `"isa_version"` from `Predicator.isa_version/0`
   (`lib/predicator/conformance/generator.ex:569`), and
   `group_by_tier/1`/`build_manifest/1` (`generator.ex:537-569`) derive the tier
   list from the opcode map, so a tier-7 file and manifest entry appear as soon
   as the opcode is registered.

There are also two soft surfaces that name tiers and would print `"tier 7"`
instead of a name if left alone: `Generator`'s `@tier_names`
(`lib/predicator/conformance/generator.ex:42-49`) and `Coverage`'s
(`lib/predicator/conformance/coverage.ex:136`).

**Three literals hard-code ISA v3** and move with the bump:
`lib/predicator/instructions.ex:45` (`@isa_version`) and its doctest at `:286`
("this build supports ISA v3"), `lib/predicator.ex:605` (the
`Predicator.isa_version()` doctest), and
`test/predicator/instructions_test.exs:11`.

### Key Discoveries

- ADR-0011 fixes the compiled form, the failure rules, and the vocabulary; none
  of it is re-argued here (`docs/adr/0011-casts-are-an-opcode.md:49-93`).
- The conversion matrix and every per-cell parse/format rule are already
  specified in
  [`docs/research/260809-px-2r5.1-cast-conversion-matrix.md`](../research/260809-px-2r5.1-cast-conversion-matrix.md).
  This bead's job is to implement it and promote it into `docs/isa.md` §5, not
  to re-derive it.
- A duration is a plain map at runtime, so `duration` and `map` sources must be
  told apart by shape. The evaluator already does this in the private
  `get_value_type/1` (`evaluator.ex:1037-1050`); the conversion module needs its
  own equivalent, and a struct-free seven-key pattern match is the cleanest one.
- `docs/isa.md` §5 names, per opcode, the evaluator functions that implement it.
  A cast implemented in its own module is a mild deviation from that phrasing
  and is handled by naming both the clause and the module function.
- CHANGELOG has no `## [Unreleased]` section today (top entry is `4.0.0`);
  `px-2r5.2` deliberately deferred the user-facing entry to this bead.

## Desired End State

`Predicator.evaluate/2,3` and `Predicator.execute/2` run `expr::type` for all
seven scalar ISA type names, over the whole conversion matrix, with
`:undefined` for every propagation and every failed conversion and no raise
anywhere. `Predicator.compile/1` emits `["cast", type_name]`.
`Predicator.isa_version/0` returns `4`. `docs/isa.md` carries the `cast` row, the
tier-7 row, a §5 subsection stating the matrix normatively, and a v4 line in §7,
and `test/predicator/isa_sync_test.exs` is green against all of it. The
conformance corpus has a tier 7 with at least enough authored cases to satisfy
the opcode-coverage rule, and `conformance/manifest.json` reads
`"isa_version": 4`.

Verify with full `mix quality` green, plus:

```
Predicator.evaluate(~s("42"::integer)) == {:ok, 42}
Predicator.evaluate(~s("abc"::integer)) == {:ok, :undefined}
Predicator.evaluate(~s(x::integer), %{}) == {:ok, :undefined}
Predicator.compile(~s("42"::integer)) == {:ok, [["lit", "42"], ["cast", "integer"]]}
Predicator.isa_version() == 4
```

## What We're NOT Doing

- **`StringVisitor` rendering and the decompile round-trip.** That is `px-2r5.4`,
  and `Predicator.decompile/2` on a cast still raises `FunctionClauseError`
  after this branch - the same accepted interim gap `px-2r5.2` recorded, now
  half-closed. Do not add a `StringVisitor` clause here.
- **The full tier-7 corpus.** `px-2r5.5` owns it. This bead authors the minimum
  the opcode-coverage rule requires plus a small representative set (below);
  it does not attempt the exhaustive per-cell corpus the research doc's "Corpus
  notes" section sketches.
- **User-facing surface documentation** - `docs/reference/language.md`, the
  README feature list, `docs/architecture.md`'s "Project Overview" paragraph.
  That is `px-2r5.6`. This bead's `docs/architecture.md` edit is one sentence in
  the ISA/opcode context only.
- **Amending `docs/isa.md` §2's "opcodes validate, they do not coerce" line.**
  ADR-0011's Consequences assigns that clarifying clause to `px-2r5.6`.
- **Any parser or lexer change**, beyond the optional single-line dedup of
  `@cast_type_names` in Phase 2. The grammar is settled and merged.
- **Bare conversion functions** (`integer(x)`), explicitly rejected by ADR-0011.
- **Widening the vocabulary** to `list` or `map`, or adding cast targets the
  matrix marks `-`.
- **A release.** ISA v4 is additive, so it ships in a minor release - but
  bumping `@version`, promoting `## [Unreleased]`, and tagging are release work
  under CLAUDE.md's authority table and need an explicit request naming a
  version.

## Implementation Approach

Three phases. The middle one is unavoidably large, and the reason is worth
stating up front so nobody "improves" the phasing by splitting it: **the moment
`"cast"` enters `Predicator.Instructions`'s `@opcodes` map, five tests demand
the evaluator clause, the doc table, the version line, a conformance case, and a
regenerated corpus all at once.** Any split of Phase 2 leaves an intermediate
`mix quality` red, which is exactly the sizing rule `/create-plan` states.

So the split is by what can be built *before* the opcode exists:

- **Phase 1** builds the whole conversion matrix as a pure, fully-tested module
  with no ISA involvement at all. This is the bulk of the work and the bulk of
  the risk, and it lands green on its own with nothing wired to it.
- **Phase 2** is the atomic wiring: compile clause, evaluator clause, opcode
  registration, ISA v4, doc, tier names, conformance cases, regenerated corpus.
- **Phase 3** is the changelog entry and the one architecture-doc sentence.

### Why a separate module rather than evaluator internals

The matrix is ~30 meaningful conversions with their own parse and format rules.
`lib/predicator/evaluator.ex` is already 1732 lines with file-level Credo
suppressions; adding the matrix inline would grow the file by a fifth and make
the conversion rules unreachable from a unit test except through an instruction
list. A separate `Predicator.Cast` also gives the parser a single home for the
seven names. The evaluator's clause stays the same three-line shape every other
opcode has.

## Phase 1: `Predicator.Cast` - the conversion matrix

### Overview

A new pure module implementing every cell of the matrix, plus the one missing
primitive it needs (`Predicator.Duration.parse/1`). No opcode, no ISA change,
nothing calls it yet. Gate-green on its own; the tests are what prove it.

### Changes Required:

#### 1. Duration parsing

**File**: `lib/predicator/duration.ex`
**Changes**: A new public `parse/1`, with `@doc` and `@spec`, mirroring
`to_string/1` as its inverse.

```elixir
@spec parse(binary()) :: {:ok, Types.duration()} | :error
def parse(string)
```

Rules, taken from the language's own duration-literal grammar
(`lib/predicator/lexer.ex:712-749`) so `"1d2h30m"::duration` means what
`1d2h30m` means in source:

- The whole string is a sequence of one or more `<digits><unit>` pairs, with no
  whitespace, no sign, and no partial consumption. An empty string is `:error`.
- The accepted units are exactly the eight the lexer accepts and
  `to_string/1` emits: `y`, `mo`, `w`, `d`, `h`, `m`, `s`, `ms`. `mo` and `ms`
  are matched before the single-character units, as the lexer does, so `"1mo"`
  is one month and not one minute followed by a stray `o`.
- Values are non-negative integers, matching the literal grammar.
- Anything else - a bad unit, a trailing character, a leading `-`, a bare
  number - is `:error`.
- Repeated units accumulate, matching `Duration.add_unit/3`'s existing behavior.

The implementation is a small recursive scan or a single anchored regex plus
`Regex.scan/2`; either is fine. It must **not** call into the lexer (private
functions) and must not compile source.

**Round-trip obligation**: `parse(to_string(d)) == {:ok, d}` for every duration
`d` that `to_string/1` can produce, including the `"0s"` empty case. Note the
asymmetry to handle deliberately: `to_string/1` omits zero components, and the
`milliseconds` key is present in a parsed duration only when a `ms` unit
appeared (`docs/isa.md` §3), so `parse("0s")` must produce the same map
`Duration.new()` does.

#### 2. The cast module

**File**: `lib/predicator/cast.ex` (new)
**Changes**: The module, with a moduledoc citing ADR-0011 and the research doc,
and two public functions.

```elixir
@doc "The seven scalar ISA type names casts accept (docs/isa.md section 3)."
@spec type_names() :: [binary()]
def type_names, do: @type_names

@doc "Converts `value` to the named type, or `:undefined` when it cannot."
@spec cast(term(), binary()) :: term()
def cast(value, type_name)
```

`cast/2` is **total over values and never returns an error tuple** - that is
ADR-0011's soft-failure rule expressed in the signature, and it is why the
evaluator clause below has no error branch other than the stack-depth one. Guard
`cast/2` on `type_name in @type_names` so a bad name is a `FunctionClauseError`
at the module boundary rather than a silent `:undefined`; the evaluator never
passes one, because its own clause guards the same list.

The clause order that makes the matrix correct:

1. `cast(:undefined, _type)` -> `:undefined`. First clause, ADR-0011 rule 1.
2. Identity clauses per type, matched on shape.
3. The conversions, below.
4. A final catch-all -> `:undefined`. This is ADR-0011 rule 2, and it is what
   makes every `-` cell in the matrix free: lists, maps, and every
   unlisted pair fall here with no per-cell code.

**Source classification.** `Date` and `DateTime` are structs and must be matched
(`%Date{}`, `%DateTime{}`) before any `is_map/1` clause. A duration is a plain
map, so it is told apart from a generic map by a seven-key pattern:

```elixir
%{years: _, months: _, weeks: _, days: _, hours: _, minutes: _, seconds: _}
```

which is `docs/isa.md` §3's normative duration shape. The optional
`milliseconds` key is deliberately not in the pattern.

The cells, restating the research doc so the implementer does not have to
context-switch (`docs/research/260809-px-2r5.1-cast-conversion-matrix.md` remains
the authority if the two ever disagree):

| From | To | Rule |
|---|---|---|
| integer | float | exact widening |
| integer | string | `Integer.to_string/1` |
| float | integer | truncate toward zero (`trunc/1`), deliberately not PG's rounding |
| float | string | `Float.to_string/1` (shortest round-trip) |
| string | integer | whole string matches `-?[0-9]+`, then `String.to_integer/1` |
| string | float | whole string matches `-?[0-9]+(\.[0-9]+)?`; no exponent form. `"3"::float` is `3.0` |
| string | boolean | exactly `"true"` / `"false"`, case-sensitive |
| string | date | `Date.from_iso8601/1` |
| string | datetime | `DateTime.from_iso8601/1`, which rejects a naive string with `:missing_offset` and normalizes to UTC |
| string | duration | `Duration.parse/1` |
| boolean | string | `"true"` / `"false"`. There is no boolean/number bridge in either direction |
| date | string | `Date.to_iso8601/1` |
| date | datetime | midnight UTC |
| datetime | string | ISO 8601 in UTC with `Z` |
| datetime | date | `DateTime.to_date/1` |
| duration | string | `Duration.to_string/1` |

Two implementation notes worth spelling out:

- **`date::datetime`** should use `DateTime.new(date, ~T[00:00:00], "Etc/UTC")`,
  which needs no time zone database. Do not reach for `shift_zone`.
- **`datetime::string`** must be UTC-normalized before formatting.
  `DateTime.to_iso8601/1` prints the datetime's own offset, and
  `DateTime.shift_zone/2` requires a tz database for a non-UTC zone. The
  tzdb-free route is `DateTime.from_unix!(DateTime.to_unix(dt, :microsecond),
  :microsecond)`, which always yields a UTC datetime, then
  `DateTime.to_iso8601/1`. In practice this library's datetimes are already UTC
  (the lexer discards the offset, `lexer.ex:656`), so this is belt-and-braces -
  but a hand-built instruction list or a host-supplied context can carry any
  datetime, so the normalization is not optional.

The regex-guard-then-parse shape for `string::integer` and `string::float` is
deliberate and must not be replaced by a bare `Integer.parse/1` /
`Float.parse/1`: the stdlib functions accept a leading `+`, accept partial
consumption, and `Float.parse/1` accepts an exponent - all three of which the
research doc's "whole string or `:undefined`; no trimming, no partial
consumption, no locale forms" rule excludes.

#### 3. Tests

**File**: `test/predicator/cast_test.exs` (new)

Structure it as one `describe` per target type, and cover, per the acceptance
criteria's "full conversion matrix including failure and `:undefined` cases":

- **Every cell of the matrix.** Each `=` cell (identity), each named conversion,
  and - this is the acceptance criterion that is easy to under-test - a
  representative `-` cell for each source type, asserting `:undefined`. A
  table-driven test over the source types crossed with `type_names/0` is a
  reasonable way to assert the whole `-` region at once.
- **The propagation rule**: `cast(:undefined, t) == :undefined` for all seven
  `t`.
- **The totality rule**: an unconvertible value against every target is
  `:undefined`, never a raise and never an error tuple.
- **Whole-string strictness**: `" 42"`, `"42 "`, `"42abc"`, `"+42"`, `"4_2"`,
  `""` are all `:undefined` for `::integer`; `"1e3"`, `".5"`, `"3."` are
  `:undefined` for `::float`.
- **Truncation sign**: `-1.5::integer` is `-1`, `1.9::integer` is `1`.
- **`"3"::float` is `3.0`** - the integer-shaped-string case.
- **Boolean strictness**: `"TRUE"`, `"True"`, `"1"`, `"yes"` are `:undefined`.
- **`::datetime` offset requirement**: `"2026-08-09T10:00:00"` is `:undefined`;
  `"2026-08-09T10:00:00Z"` and `"2026-08-09T12:00:00+02:00"` both give the same
  UTC datetime.
- **`::date` strictness**: `"2026-08-09T00:00:00Z"` is `:undefined` for
  `::date` (the supported spelling is `::datetime::date`); `"2026-8-9"` is
  `:undefined`.
- **Date/datetime bridge**: `date::datetime` is midnight UTC;
  `datetime::date` drops the time; a non-UTC datetime formats with `Z`.
- **No boolean/number bridge**: `1::boolean`, `0::boolean`, `true::integer`,
  `true::float` are all `:undefined`.
- **Lists and maps**: `[1,2]` and `%{"a" => 1}` are `:undefined` for every
  target including `::string`.
- **Duration**: `to_string`/`parse` round-trip in both directions, the `"0s"`
  case, the `ms` key present only when used, `"1mo"` vs `"1m"`.
- **`type_names/0`** returns exactly the seven names in ISA order.

**File**: `test/predicator/duration_test.exs` (existing)
A `describe "parse/1"` block: each of the eight units alone, a multi-unit
string, the `mo`/`ms` disambiguation, accumulation on a repeated unit, and the
rejections (empty, negative, float value, unknown unit, trailing junk, leading
or embedded whitespace, a bare number, `"1d "`).

## Phase 2: The `cast` opcode and ISA v4

### Overview

The atomic phase. Registers the opcode, emits it, runs it, documents it, and
regenerates the corpus. Every item below has to be in the same commit or the
gate is red - see "Implementation Approach" for why.

### Changes Required:

#### 1. Compile the node

**File**: `lib/predicator/visitors/instructions_visitor.ex`
**Changes**: One `visit_annotated/2` clause, placed next to `property_access`
(`:185-189`) so the three postfix forms sit together.

```elixir
defp visit_annotated({:cast, expr, type_name, position}, opts) do
  visit_annotated(expr, opts) ++ [{["cast", type_name], position}]
end
```

The node's own position slot is what the instruction is annotated with, which
`px-2r5.2` already defined as the type-name token (`docs/reference/ast.md`) -
so a failed cast blames the type the author wrote. Nothing else is owed: the
position and span tables are derived generically by `tables/1`
(`instructions_visitor.ex:139-162`).

#### 2. Run the opcode

**File**: `lib/predicator/evaluator.ex`
**Changes**: A dispatch clause among the others (`:446-603`), and one helper.

```elixir
defp execute_instruction(%__MODULE__{} = evaluator, ["cast", type_name])
     when is_binary(type_name) and type_name in @cast_type_names do
  execute_cast(evaluator, type_name)
end
```

```elixir
defp execute_cast(%__MODULE__{stack: [value | rest]} = evaluator, type_name) do
  {:ok, %__MODULE__{evaluator | stack: [Cast.cast(value, type_name) | rest]}}
end

defp execute_cast(%__MODULE__{stack: stack}, _type_name) do
  {:error, EvaluationError.insufficient_operands(:cast, length(stack), 1)}
end
```

with `@cast_type_names Predicator.Cast.type_names()` as a module attribute and
an `alias Predicator.Cast`. Points that matter:

- **The `in @cast_type_names` guard is load-bearing.** It is what makes
  `["cast", "widget"]` and `["cast", 5]` fall through to the catch-all
  (`evaluator.ex:601-603`) and return `unknown_instruction`, which is the
  standing malformed-operand rule ADR-0011 relies on and the only error path
  `cast` has besides an empty stack.
- **There is no other error branch**, by design. `Cast.cast/2` is total, so a
  failed conversion pushes `:undefined` and the run continues.
- The clause-head shape must keep matching
  `isa_sync_test.exs:298`'s regex - `["cast"` immediately after the
  `%__MODULE__{}` argument - or the sync test silently stops counting it.

**File**: `test/predicator/instructions_test.exs`

**File**: `test/predicator/isa_sync_test.exs`

**Changes**, all four of them - each one is separately asserted by

## ISA Impact

1. **Version** - **this mints ISA v4**, and v4 is **additive**: one new opcode,
   nothing retired, every existing instruction list still valid and still
   meaning what it meant. Per `docs/isa.md` §1 and ADR-0003 that ships in a
   **minor** library release. `Predicator.Instructions.@isa_version` moves
   3 -> 4 and `docs/isa.md` §1's current-version line moves with it.
2. **Stamp** - `docs/isa.md` owes four edits: the §4 opcode row
   (`cast`, operand a type-name string, pops 1, pushes 1, v4, tier 7, emitted by
   the compiler, not removed), a §4 tier-table row minting **tier 7, `casts`**,
   a §5 subsection carrying the conversion matrix as **normative** semantics
   (not a function-layer option - a sibling claiming v4 implements exactly this
   matrix), and a §7 history row. `Predicator.Instructions`'s `@opcodes` gains
   `"cast" => %{isa: 4, tier: 7}`. The conformance corpus gains
   `conformance/corpus/tier-7.json`, generated from
   `conformance/cases/casts.json`.
3. **Migration** - **none required.** No stored artifact contains `cast`, no
   existing opcode changed, and no instruction list compiled before this change
   produces a different answer after it. The only version-sensitive consequence
   is the ordinary one ADR-0003 documents: an instruction list containing `cast`
   reports `required_isa/1` of `4`, and a sibling claiming v1, v2, or v3 will
   correctly refuse it up front. Both siblings being behind v4 is an expected,
   documented state and is not a blocker on this change.

## Open Questions

Recorded rather than resolved: this was an unattended planning run with no human
available. Each carries a working decision, and none blocks implementation.

1. **This branch touches two areas the bead is not labeled with.** `px-2r5.3`
   carries `area:docs` and `area:evaluator`, but the compile clause is in
   `lib/predicator/visitors/instructions_visitor.ex` (`area:visitors`) and the
   corpus work is in `conformance/**` plus `lib/predicator/conformance/**`
   (`area:conformance`). Per CLAUDE.md that is "worth noticing at merge time,
   not silently accepting" - and it has a live consequence: **`px-2r5.4` is the
   StringVisitor bead and carries `area:visitors`, so it is not batchable with
   this one**, which the label sets as written would have said it was.
   **Working decision: proceed, add both labels to the bead
   (`bd update px-2r5.3 --labels ...`), and do not run `px-2r5.4` in parallel.**
   **Open:** whether the epic's labels should have anticipated this, and whether
   the corpus half should instead have been split into `px-2r5.5`.

2. **How much corpus to author here.** `opcode_coverage_test` forces at least
   one case into this bead, which means `px-2r5.5`'s boundary is soft. **Working
   decision: the six representative cases listed in Phase 2**, chosen to pin the
   rules a sibling is most likely to get wrong, leaving the exhaustive per-cell
   corpus (float-format pinning, every parse's whole-string strictness, the
   duration round-trip both ways) to `px-2r5.5`. **Open:** whether the human
   would rather see the absolute minimum here and everything in `px-2r5.5`.

3. **`Predicator.Cast` as a public module.** It gets `@doc`/`@spec` per project
   convention, which makes `Predicator.Cast.cast/2` a documented, callable API
   with no `::` involved - arguably a second surface for conversion, which
   ADR-0011's "No bare conversion functions" bullet is hostile to. **Working
   decision: public, because the ADR's objection is to a *predicate-language*
   surface (a registry name colliding with user variables, two spellings the
   StringVisitor would have to choose between), not to an Elixir module; and
   `Predicator.Duration` is the existing precedent for a public value-layer
   module.** It is not re-exported on `Predicator`. **Open:** whether the
   moduledoc should say "not part of the predicate surface" explicitly, or
   whether the module should be `@moduledoc false`.

4. **`float::string` portability.** The matrix specifies "shortest round-trip
   decimal" and `Float.to_string/1` provides it, but the research doc already
   flags this as a known cross-language hazard and pushes the mitigation into
   the corpus ("pin values chosen to format identically"). **Working decision:
   use `Float.to_string/1`, pin only portable values in the cases authored here,
   and leave the systematic pinning to `px-2r5.5`.** **Open:** whether
   `docs/isa.md` §5 should state a narrower, explicitly portable rule instead of
   "shortest round-trip".

5. **The §7 history row's "Shipped in" cell.** ISA v4 is additive so the release
   is a minor - `4.1.0` on the current line - but the release is not this bead's
   to declare (CLAUDE.md's authority table: release mechanics need an explicit
   request naming a version). **Working decision: write `4.1.0` in the cell and
   call it out in the PR body** so a human can correct it before the release
   lands. **Open:** whether the row should instead be added at release time.

6. **`px-2r5.4`'s remaining interim gap.** After this bead, evaluation works but
   `Predicator.decompile/2` on a cast still raises `FunctionClauseError` -
   `px-2r5.2`'s open question #1, now half-closed. **Working decision:
   unchanged - accept it, do not add a placeholder `StringVisitor` clause one
   bead before `px-2r5.4` deletes it.**
