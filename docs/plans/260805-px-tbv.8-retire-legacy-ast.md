# Retiring the Pre-4.0 AST Shape Acceptance Implementation Plan

## Overview

Cuts the pre-4.0 AST compatibility layer in one piece: `Parser.strip_positions/1`,
`Parser.ensure_positions/1`, their private object-key helpers, and the
`bare_ast/0` / `bare_object_key/0` types all go. After this, the AST has exactly
one shape - every node carries a trailing slot holding a position, a span, or
`nil` - and the visitors consume that shape directly with no normalization at
their entry points.

Beads issue: px-tbv.8. Lands with px-tbv.7 so 4.0.0 carries one AST break rather
than two.

## Current State Analysis

### The layer being removed

`Parser.strip_positions/1` (`lib/predicator/parser.ex:331-408`) has two clause
families: 17 arms that drop a node's trailing slot, and 15 arms that accept an
already-bare node so the function is idempotent on 3.6 input. `strip_entry/1`
and `strip_object_key/1` (`parser.ex:410-423`) lower an `{:object_key, value,
style, pos}` node back to the 3.6 key shape, discarding `style`.

`Parser.ensure_positions/1` (`parser.ex:441-526`) is the inverse: its arity-N
arms append `nil` to a bare node, its arity-N+1 arms recurse through a
positioned one. `ensure_entry/1` and `ensure_object_key/1` (`parser.ex:528-545`)
absorb four pre-4.0 key shapes - 3.6 bare `{:identifier, name}` /
`{:string_literal, value}` and 3.7 positioned `{:identifier, name, pos}` /
`{:string_literal, value, pos}` - lifting each to `{:object_key, value, style,
pos}`, defaulting a styleless string key to `:double`.

Three call sites in `lib/` normalize on the way in:

- `Predicator.Visitors.StringVisitor.visit/2` - `string_visitor.ex:89-93`
- `Predicator.Visitors.InstructionsVisitor.annotate/2` - `instructions_visitor.ex:113-118`
- `Predicator.ContextLocation.resolve/2` - `context_location.ex:127`

Six `@spec`s widen their input to `Parser.ast() | Parser.bare_ast()`:
`compiler.ex:50`, `compiler.ex:78`, `compiler.ex:116`, `visitor.ex:52`,
`visitor.ex:65`, `instructions_visitor.ex:72`, `instructions_visitor.ex:96`,
`instructions_visitor.ex:113`, `string_visitor.ex:88`.

### Key discoveries

- **Every visitor clause already has exactly one form.** `do_visit/2` in
  `StringVisitor` and `visit_annotated/2` in `InstructionsVisitor` match only
  the positioned arity; the bare shape never reaches them. Deleting
  `ensure_positions/1` is therefore a deletion at the call sites, not a rewrite
  of the visitors.
- **Neither visitor has a catch-all clause.** An unrecognized node already
  raises `FunctionClauseError` today (`ensure_positions/1` passes it through
  unchanged, then `do_visit/2` fails to match). So a bare AST passed after this
  change fails the same way any junk node already does - no new error path is
  needed, and none is added. `ContextLocation.do_resolve_base/2` does have a
  catch-all (`context_location.ex:305`) returning
  `LocationError.invalid_node/2`; a bare node will land there instead of
  raising, which is the correct behavior for that module and needs no change.
- **`strip_positions/1` is used in `test/` as a shape helper, not as an API
  under test.** Eleven test files call it, almost all through a private
  `parse_positionless/1`-style wrapper (e.g. `parser_test.exs:1499-1509`) whose
  comment says the assertions are about AST *shape*. Positions themselves are
  covered separately by `parser_positions_test.exs` and `parser_spans_test.exs`.
  So the helper's job survives the function's removal and moves into test
  support.
- **There is no `test/support` directory and no `elixirc_paths` in `mix.exs`,**
  but `test/test_helper.exs` already defines a shared module,
  `Predicator.SpanSlicing`. That is the precedent the new stripper follows.
  Adding `elixirc_paths` would touch `mix.exs` and pull in the exclusive
  `area:build` label (CLAUDE.md), which this bead must not do.
- **`docs/architecture.md:281-296`** documents the normalizers as an
  architectural boundary and already flags the acceptance as "scheduled for
  removal in 4.0.0 (see px-tbv)". Step 7 of "Adding New Operators"
  (`architecture.md:875-876`) instructs a contributor to widen both functions
  for a new node.
- **The `=`-as-equality doctests** in `StringVisitor` and `Predicator.decompile/2`
  are untouched by this bead; `=` stays parseable in 3.x and its removal is
  px-tbv's separate grammar break. Rewriting a doctest's AST shape here does not
  change its operator.

## Desired End State

- `Predicator.Parser` exports `parse/2` and the AST types, and nothing else
  about shape normalization. `strip_positions/1`, `ensure_positions/1`,
  `bare_ast/0`, and `bare_object_key/0` do not exist.
- Every `@spec` that took `Parser.ast() | Parser.bare_ast()` takes
  `Parser.ast()`.
- `Predicator.decompile/2`, `Compiler.to_instructions/2`,
  `Compiler.to_string/2`, and `ContextLocation.resolve/2` require a node with a
  trailing slot. The slot may be `nil`, so a hand-built AST is still possible -
  `{:literal, 42, nil}` - it just has to say so.
- `docs/architecture.md` describes a single AST shape with no boundary
  normalizers, and its "Adding New Operators" checklist no longer tells a
  contributor to widen two functions that are gone.
- `CHANGELOG.md`'s `## [Unreleased]` carries a `### Removed` entry naming both
  functions, both types, and the migration for a caller who was passing a
  3.6-shaped AST.

Verification: `mix quality` is green, and `grep -rn "strip_positions\|ensure_positions\|bare_ast\|bare_object_key" lib test docs README.md` returns only historical `CHANGELOG.md` and `docs/plans/` matches.

## What We're NOT Doing

- **Not adding a replacement builder API.** No `Predicator.AST.literal/1` or
  similar convenience for constructing nodes with `nil` slots. If hand-building
  proves awkward in practice that is a separate bead, and it should be designed
  against real use rather than speculatively.
- **Not adding a friendly error for a bare AST.** A bare node raises
  `FunctionClauseError` in the visitors, exactly as any unrecognized node does
  today. Introducing a special-cased error message would be a new form of
  compatibility awareness for the shape we are removing.
- **Not touching the `=` deprecation, the grammar, the lexer, the instruction
  set, or the evaluator.** No instruction changes, so no cross-language impact
  (ADR-0001).
- **Not cleaning up the dead `{:unary_minus, _}` / `{:unary_bang, _}` clauses**
  in `ContextLocation.do_resolve_base/2` (`context_location.ex:287-293`). They
  are pre-4.0 leftovers of a different lineage - the parser has never emitted
  those tags in the positioned era - and removing them is unrelated dead-code
  work that would widen this diff's area footprint for no gain here. Worth its
  own bead.
- **Not renaming or restructuring the visitor tests** beyond the mechanical
  shape rewrite.
- **Not changing `mix.exs`.** The test stripper lives in `test_helper.exs`
  specifically to avoid the exclusive `area:build` label.

## Implementation Approach

The work splits at a seam that keeps every intermediate state green: because
`ensure_positions/1` and `strip_positions/1` are both idempotent and tolerant of
positioned input, **every caller can be moved to the positioned shape while the
normalizers are still in place**. Phase 1 does exactly that and the full gate
passes with the compatibility layer untouched. Phase 2 is then a pure deletion:
nothing calls the functions, so removing them changes no behavior. Phase 3 is
documentation.

That ordering also makes the risk visible in the right place. If phase 1 misses
a call site, phase 2's compile and gate run surfaces it immediately rather than
burying it in a mixed diff.

Per the invocation, all three phases land as **one commit** at the end via
`/commit --auto`; the phases are units of verification and review, not of
commit.

### Area labels

The bead carries `area:docs` and `area:lexer-parser`. The work also touches
`lib/predicator/visitors/**` (`area:visitors`), `lib/predicator/compiler.ex`
(`area:evaluator`), `lib/predicator.ex` (`area:api`), and
`lib/predicator/context_location.ex` (`area:context`). Per CLAUDE.md a branch
touching an unlabeled area is worth noticing rather than silently accepting, so
the missing labels are added to the bead as part of this work:

```bash
bd update px-tbv.8 --labels area:visitors,area:evaluator,area:api,area:context
```

This does not make the bead un-batchable retroactively; it records that the
prediction was too narrow, which is the point of the rule.

## Phase 1: Move every caller onto the positioned shape

### Overview

Rewrite every bare AST in `test/` and in `lib/` documentation to the positioned
shape, and replace the tests' use of `strip_positions/1` with a test-support
stripper. The normalizers stay in place; the gate must be green at the end of
this phase with them untouched.

### Changes Required:

#### 1. Test-support stripper

**File**: `test/test_helper.exs`
**Changes**: Add a `Predicator.ASTShape` module beside the existing
`Predicator.SpanSlicing`. It drops each node's trailing slot and recurses -
mirroring today's `strip_positions/1` minus the bare arms, and **without** the
3.6 object-key lowering: an object key strips to `{:object_key, value, style}`,
keeping `style`, because the 3.6 key shape is precisely what this bead retires.

```elixir
defmodule Predicator.ASTShape do
  @moduledoc """
  Drops the trailing source slot from every node of an AST.

  Most parser assertions are about node *shape* - what the tree is - while
  positions and spans have their own suites (`parser_positions_test.exs`,
  `parser_spans_test.exs`). This lets those assertions read as the shape they
  mean. It is test-only: `Predicator.Parser` has no position-stripping function
  as of 4.0, because the AST has one shape and consumers are expected to keep
  the slot.
  """

  @doc "Returns `ast` with every node's trailing slot removed."
  @spec strip(term()) :: term()
  def strip({:literal, value, _slot}), do: {:literal, value}
  def strip({:string_literal, value, quote_type, _slot}), do: {:string_literal, value, quote_type}
  def strip({:identifier, name, _slot}), do: {:identifier, name}
  def strip({:duration, units, _slot}), do: {:duration, units}

  def strip({:comparison, op, left, right, _slot}),
    do: {:comparison, op, strip(left), strip(right)}

  def strip({:arithmetic, op, left, right, _slot}),
    do: {:arithmetic, op, strip(left), strip(right)}

  def strip({:membership, op, left, right, _slot}),
    do: {:membership, op, strip(left), strip(right)}

  def strip({:unary, op, operand, _slot}), do: {:unary, op, strip(operand)}
  def strip({:logical_and, left, right, _slot}), do: {:logical_and, strip(left), strip(right)}
  def strip({:logical_or, left, right, _slot}), do: {:logical_or, strip(left), strip(right)}
  def strip({:logical_not, operand, _slot}), do: {:logical_not, strip(operand)}
  def strip({:list, elements, _slot}), do: {:list, Enum.map(elements, &strip/1)}
  def strip({:object, entries, _slot}), do: {:object, Enum.map(entries, &strip_entry/1)}

  def strip({:function_call, name, args, _slot}),
    do: {:function_call, name, Enum.map(args, &strip/1)}

  def strip({:bracket_access, object, key, _slot}),
    do: {:bracket_access, strip(object), strip(key)}

  def strip({:property_access, object, property, _slot}),
    do: {:property_access, strip(object), property}

  def strip({:relative_date, duration, direction, _slot}),
    do: {:relative_date, strip(duration), direction}

  def strip(node), do: node

  defp strip_entry({{:object_key, value, style, _slot}, node}),
    do: {{:object_key, value, style}, strip(node)}
end
```

Note the deliberate difference from the retired `strip_positions/1`: it is not
idempotent and does not need to be. It is applied once, to parser output.

## Testing Strategy

### Unit Tests:
- The visitor suites keep their existing coverage, rewritten to the positioned
  shape - the assertions themselves do not change, only the node arity.
- Object-key assertions gain `style`, so single- vs double-quoted keys are now
  distinguished in tests that previously could not express the difference.
- The `ASTShape.strip/1` helper is not itself tested: it is a test fixture, and
  a bug in it fails the assertions that use it.

### Integration Tests:
- The corpus round-trip test added in phase 1 (`string_visitor_test.exs`) is the
  load-bearing one: 23 expressions covering every node type, parsed and fed to
  the visitors with no normalization step. It passes in phase 1 with the
  normalizers present and must still pass in phase 2 with them gone - which is
  what proves the removal changed no behavior for parser output.
- `test/predicator/integration/` and `docs_examples_test.exs` exercise the
  string entry points end to end and should need no edits; if one does, a bare
  AST was reaching a visitor through a path this plan did not enumerate.

### Manual Testing Steps:
1. `iex -S mix`, then `Predicator.decompile({:literal, 42})` - confirm
   `FunctionClauseError`, and that the message names `do_visit/2` rather than
   something misleading.
2. `Predicator.decompile({:literal, 42, nil})` returns `"42"` - hand-built ASTs
   still work with an explicit slot.
3. `Predicator.compile_with_positions/1` on a parsed expression still returns a
   populated side table; on a `nil`-slotted hand-built AST it returns `%{}`.
4. `Predicator.ContextLocation.resolve({:identifier, "user"}, %{})` returns an
   `invalid_node` error tuple, not a raise.

## Performance Considerations

Removing a full traversal from three hot entry points is a small win: every
`decompile/2`, `to_instructions/2`, and `resolve/2` call previously rebuilt the
entire tree through `ensure_positions/1` before doing any work. Nothing here
needs measuring, but the change is strictly in the right direction.

## Cross-Language Impact

None. The instruction set, the side table, and the interchange format are
untouched; this is an Elixir-side API shape change only (ADR-0001). The Ruby and
JavaScript siblings need no work.
